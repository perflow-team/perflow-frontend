# 스크롤 연속 읽기 검증

스크롤 모드에서 현재 화의 끝까지 읽은 뒤 다시 아래로 스크롤하면 다음 화의 처음으로 이동한다. 다음 화 본문을 미리 가져오며, 가져오기 실패 시 현재 화와 읽기 위치를 유지한다. 하단 버튼으로도 재시도할 수 있다. 마지막 화에는 완독 안내를 표시하고 다음 회차 버튼을 비활성화한다.

- 휠: 하단 도달 후 400ms 이상 경과하고, 이전 휠 입력과 240ms 이상 간격이 있는 새 동작에서 누적 80px 이상 내려야 전환한다. 기존 스크롤 관성, 크기 변경, 화면 진입만으로 전환하지 않는다.
- 터치: 하단에서 새로 시작한 위쪽 스와이프가 60px 이상일 때 전환한다. 처음부터 하단에 있지 않은 스와이프, 가로 이동, 아래쪽 이동, 다중 터치 및 취소는 제외한다.
- 키보드: 본문에 포커스가 있을 때 하단의 새로운 ArrowDown/PageDown/Space 입력을 지원하며 길게 누르는 반복 입력은 제외한다.
- 진도: 회차와 위치를 한 번에 갱신한다. 회차를 떠날 때 대기 중인 저장을 반영하고 요청을 순서대로 보내, 이전 화 저장이 다음 화 진도를 뒤늦게 덮어쓰지 않도록 한다. 비로그인 상태는 서버에 진도를 저장하지 않는다.
- 페이지 넘기기 모드는 기존 동작을 유지한다.

## 검증 결과 (2026-09-20)

- `node --test tests/*.test.mjs`: 11개 통과. 관성, 짧은 회차, 위로 이동, 크기 변경, 터치 방향/취소, 키보드 반복, 실패 후 재시도 및 저장 flush를 포함한다.
- TypeScript 빌드, Vite 프로덕션 빌드 및 lint 통과.
- 실제 UI 검증: `/tests/fixtures/continuation.html`에서 전체 앱과 실제 ReaderPage를 사용한다. 모든 API를 로컬 어댑터로 대체하므로 운영 DB에 쓰지 않는다.
- 첫 스크롤로 1화 하단에 도달해도 1화를 유지하고, 추가 스크롤로 2화 첫 위치(0%)로 전환됨을 확인했다. 저장 순서도 `1화 100% → 2화 0%`로 확인했다.
- 2화에서 3화로 전환한 후 완독 안내를 확인했고, 마지막 화에서 추가 스크롤해도 이동하지 않았다.
- 다음 화 불러오기를 강제로 실패시켰을 때 1화/100%를 유지했다. 복구 후 다시 스크롤하자 2화/0%로 전환했다.
- 터치 제스처 판정은 자동 테스트로 검증했다. 실제 모바일 기기의 터치 동작은 별도 확인이 필요하다.

테스트 화면은 개발 서버 전용이며 프로덕션 빌드 진입점에는 포함되지 않는다. 운영 반영에는 프런트엔드 배포가 필요하다.
