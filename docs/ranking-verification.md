# 랭킹 분리 및 상위 작품 조정

운영 백엔드의 이전 `/api/novels/ranking`은 `popular`를 422로 거절하고,
등록일이 없는 신작을 빈 목록으로 반환했다. 배포된 서버 버전의 영향을 피하기 위해
홈과 랭킹 페이지는 `/api/novels`의 실제 집계 필드를 같은 정렬 함수로 처리한다.
장르 필터를 적용한 전체 목록을 정렬한 뒤 요청 개수로 자른다. 요청 오류는 그대로 표시한다.

- 조회순: 조회수 내림차순, 동률이면 ID 오름차순.
- 인기순: 별점 내림차순, 동률이면 조회수 내림차순, ID 오름차순.
- 신작: `is_new`인 작품만 포함하고 미래 등록일은 제외한다. 등록일 내림차순이며,
  등록일 없는 기존 작품은 뒤에 ID 내림차순으로 표시한다. 날짜를 임의 생성하지 않는다.
- 별점순도 유지한다. 모든 목록에 실제 위치에 맞는 순위를 표시한다.

사용자 요청에 따라 백엔드 `update_ranking_baselines.py`로 2~5번의 조회수·좋아요 초기값을
조정했다. 이후 인기순을 별점 기준으로 변경하면서 5번 태평천하의 별점만 8.3에서 8.5로 올렸다. 사용자 좋아요, 신작 표시와 6~20번 작품의 수치는 보존했다.

| 순위 | 조회순 | 인기순 | 신작 |
| --- | --- | --- | --- |
| 1 | 동백꽃 | 동백꽃 | 화수분 |
| 2 | 운수 좋은 날 | 봄봄 | 레디메이드 인생 |
| 3 | 날개 | 소나기 | 사랑손님과 어머니 |
| 4 | 탁류 | 탁류 | 봄봄 |
| 5 | 태평천하 | 사랑손님과 어머니 | 태평천하 |

정렬·동률·신작 누락/미래 날짜·원본 배열 보존·장르 전달·운영 API 호환성을 단위 테스트했다.
TypeScript·프로덕션 빌드·lint 및 실제 운영 데이터로 로컬 홈의 세 목록과 순위를 확인했다.
인기순 6~10위는 날개(8.9), 삼대(8.8), 물레방아(8.7), 운수 좋은 날(8.6), 태평천하(8.5)다. 실제 DB에서 1~5번 작품이 상위 10권에 포함됨을 확인했다. 이후 별점과 조회수 변화에 따라 순위는 바뀔 수 있다.
