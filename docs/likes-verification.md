# 누적 좋아요 검증

상세 버튼은 `POST /api/novels/{id}/like`에 원하는 `liked` 값을 보낸다.
서버가 반환한 `likes`와 `is_favorite`를 표시하고 목록·랭킹·관심작 캐시를 갱신한다.
기존 초기 수치에 계정별 좋아요를 누적하며 같은 요청을 재전송해도 중복 집계하지 않는다.
좋아요 취소 시 본인의 1표를 제거한다. 상세 선택 상태와 관심작 캐시는 계정별로 분리한다.

실제 화면 검증은 운영 계정과 분리한 로컬 fixture에서 진행했다.
프로덕션 빌드에는 fixture가 포함되지 않으며 모든 요청은 테스트 adapter 안에서 처리한다.

```sh
npx vite --host 127.0.0.1 --port 4181 --strictPort
```

`http://127.0.0.1:4181/tests/fixtures/likes.html`을 열어 아래 순서로 확인할 수 있다.
이 전용 포트에서만 실행한다. 테스트 표는 이 origin의 `perflow-like-fixture`에 보관한다.

- 비로그인: 누적 18,420 표시, 좋아요는 로그인 링크.
- 계정 101: 누르면 18,421, 선택됨. 새로고침해도 수치·선택 유지.
- 계정 102: 동일한 누적 18,421, 본인 선택은 해제 상태. 누르면 18,422.
- 다음 요청 실패를 누른 뒤 취소: 수치·선택 유지, 재시도 안내.
- 다시 취소: 18,421, 선택 해제. 계정 102의 관심작은 비어 있음.
- 계정 101로 전환: 관심작에 작품이 남아 있고 좋아요 18,421 표시.
- 랭킹: 같은 누적 18,421 표시.

위 흐름을 실제 브라우저에서 확인했다. 서버의 SQLite 격리 테스트는 인증, 두 계정의 합산,
초기 수치 보존, 중복 요청의 멱등성, 취소 및 관심작 분리를 검증한다.
프론트 TypeScript·프로덕션 빌드·lint·단위 테스트 23개와 관련 백엔드 테스트 15개를 통과했다.

운영 API 읽기 확인: 작품 1~5의 첫 회차는 모두 사전 준비 완료이며 용어 목록과 설명 응답이 있다.
동백꽃·운수 좋은 날·날개는 각각 4·5·6화이다. 원제·인기순 등 새 API 코드를 포함한 프론트/백엔드 배포 상태는 각 호스팅 서비스에서 확인한다.

## 원격 랜딩 페이지와 통합

원격 `3b892b2`의 새 레이아웃과 모바일 목록을 유지했다. 카드와 모바일 목록의 임시 좋아요도
상세 버튼과 같은 API 및 계정별 관심작 캐시를 사용한다. 모든 화면에 정확한 누적 수를 표시한다.
기존 초기 수치를 바꾸지 않으며, 신작 정렬도 서버의 신작 랭킹을 따른다.
원격에서 제거된 기존 단위 테스트 수와 앞 절의 통합 이전 결과를 구분한다.
통합 후에는 원제 검색 테스트, TypeScript·빌드·lint와 격리된 실제 브라우저의 좋아요 흐름을 다시 검증한다.
